# 워체스트 (Warchest) - 수정 & 배포 안내

## 이번에 고친 멀티플레이 버그들

1. **보드 클릭 핸들러가 죽은 코드를 가리키고 있었음**
   - 실제 클릭 이벤트는 `performActionOnBoard()`를 호출하는데, 정작 팀 구분·소켓 동기화가
     구현된 `onHexClick()`은 어디서도 호출되지 않는 죽은 함수였습니다.
   - `performActionOnBoard()`에 팀 동적 처리 + 소켓 전송 + 특수능력(파이크/방패/기마병/검사)
     로직을 전부 합쳐서, 클릭 즉시 상대 화면에도 정확히 반영되도록 고쳤습니다.

2. **모든 로직이 "나는 항상 blue팀"으로 하드코딩되어 있었음**
   - `unitOwner === 'blue'` 등 40여 곳을 `myTeam`(내 팀) 기준으로 동적 비교하도록 수정.
   - red팀으로 접속하면 자기 유닛을 아예 조작할 수 없던 근본 원인이었습니다.

3. **오프닝 연출에서 주머니가 항상 blue팀 픽으로만 만들어짐**
   - red팀 클라이언트도 `bluePicked`를 사용해 주머니를 만들고 있어 완전히 잘못된 유닛 구성으로
     시작했습니다. `myPickedUnits`(내가 실제로 뽑은 유닛)로 수정.

4. **상대방 행동 수신 함수(`applyRemoteAction`)가 존재하지 않는 변수(`boardUnits`)를 참조**
   - 상대 턴이 끝나도 내 화면에는 아무 것도 반영되지 않던 버그. `hexGridData`를 직접
     갱신하도록 재작성했고, 전투로 죽은 유닛을 묘지(graveyard)에도 반영하도록 수정.

5. **"지시"(군기 명령) 능력이 완전히 작동 안 함**
   - 액션 이름이 `'지시'`인데 클릭 핸들러는 `'지시_대상선택'`을 검사하고 있어서 매칭이 안 됐음.
   - 명령을 통한 이동/공격 시 토큰 소모가 안 되던 자원 버그도 함께 수정.

6. **석궁사수 특수 능력 미작동** — 코드에서는 `'석궁 사수'`(띄어쓰기 O)로 비교했지만
   실제 유닛 이름은 `'석궁사수'`(띄어쓰기 X)라 항상 매칭 실패. 통일함.

7. **파이크병 반격이 일반 공격에서는 발동 안 함** — 근접 공격의 `attackType` 값이
   `'근접공격'`으로 저장되어 반격 조건(`=== '근접'`)과 어긋났던 문자열 불일치 수정.

8. **연결이 끊긴 상대를 알 방법이 없었음** — 서버에 disconnect 처리 추가, 남은 플레이어에게
   알림(`playerLeft`)을 보내고 빈 방은 메모리에서 정리하도록 함.

## 새로 추가한 기능

### 왕국 토큰 선공권 확보
- 손패에 왕국 토큰이 들어오면 `패스 / 주도권 확보 / 징집` 중 선택할 수 있습니다.
- **주도권 확보**를 사용하면 토큰을 소모하는 대신, 이번에 내 손패를 모두 사용한 직후
  턴이 상대에게 넘어가지 않고 **우리 팀이 연속으로 턴을 가져갑니다.**
- 서로 눈치싸움을 하며 언제 주도권을 챙길지 고민하는 것이 새로운 전략 포인트입니다.

### 전장 축소
- 기존 7열(23칸) 보드를 5열(14칸, 2-3-4-3-2 구조)로 축소했습니다.
- 거점(control) 3곳은 그대로 유지되어 "거점 3곳 선점 승리" 조건과 자연스럽게 맞습니다.
- 진영 기지는 대각선으로 마주보게 배치해 공평한 거리감을 유지했습니다.

## 로컬 실행

```bash
npm install
node server.js
```

브라우저에서 `http://localhost:3000` 접속 (같은 방 번호로 두 개의 탭/기기에서 접속하면
자동으로 blue/red 팀이 배정됩니다).

## 실제 배포 (Render.com 기준, 무료)

1. 이 폴더를 GitHub 저장소로 올립니다 (Codespace 터미널에서):
   ```bash
   git init
   git add .
   git commit -m "워체스트 멀티플레이 수정 + 왕국 토큰 기능"
   git branch -M main
   git remote add origin https://github.com/<내계정>/warchest.git
   git push -u origin main
   ```
2. https://render.com 가입 후 **New + → Web Service** 선택.
3. 방금 올린 GitHub 저장소를 연결합니다.
4. 설정값:
   - **Build Command**: `npm install`
   - **Start Command**: `node server.js`
   - **Instance Type**: Free
   - Render가 `PORT` 환경변수를 자동으로 주입하며, `server.js`는 이미
     `process.env.PORT`를 사용하도록 되어 있어 그대로 작동합니다.
5. 배포가 끝나면 `https://<서비스이름>.onrender.com` 주소가 생기고, 이 주소를 친구에게
   공유하면 바로 같이 플레이할 수 있습니다.
   - 무료 플랜은 일정 시간 트래픽이 없으면 서버가 잠들었다가 첫 접속 시 10~30초 정도
     깨어나는 시간이 걸릴 수 있습니다. 계속 상시 가동을 원하면 유료 플랜(월 $7~)이 필요합니다.

**대안**: Railway.app도 Node + WebSocket을 무료 크레딧으로 지원하며 절차가 거의 동일합니다.

## 알려진 제한 사항 (이번 범위 밖)
- 새로고침/재접속 시 게임 상태 복구는 지원하지 않습니다 (서버가 게임판 상태를 저장하지 않음).
- 서버는 클라이언트가 보낸 행동을 그대로 신뢰합니다(치팅 방지 없음) — 친구끼리 하는
  캐주얼 플레이를 가정한 구조입니다.
